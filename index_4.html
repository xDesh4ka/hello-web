1. Что такое backend

⚙️

Серверная часть приложения: принимает запрос, применяет правила, работает с данными и возвращает ответ.

Модуль 1: ОсновыSlide #4

Базовый цикл работы backend

→
⚙️Backendобрабатывает запрос
→
✅Ответвозвращает результат
Главная модельОдин запрос приводит к одному ответу, даже если внутри backend обращался к нескольким системам.

Клиент отправляет POST /tasks

В теле передаёт title и дополнительные поля.

2
Backend проверяет данные

Пустой title не проходит валидацию.

3
Применяется бизнес-логика

Проверяются права и лимит активных задач.

4
Запись сохраняется

База данных возвращает идентификатор.

5
Клиент получает 201

В ответе приходит созданная задача в JSON.

Модуль 16: SQLSlide #48

Параметризованный SQL

FROM tasks

Модуль 17: ORMSlide #52

Скрытая цена абстракции

  • ORM не отменяет необходимость понимать SQL и индексы.
  • Ленивая загрузка может создать проблему N+1 запросов.
  • Сложный отчёт иногда проще и быстрее выразить SQL.
  • Объектная модель не всегда совпадает с оптимальной формой данных.
  • Сгенерированный SQL нужно наблюдать и анализировать.
Инженерный подходАбстракция полезна, пока команда понимает её поведение.

Количество workers выбирают по профилю нагрузки, памяти и измерениям. Больше процессов не означает бесконечный рост производительности.

23. Состояние между запросами

🧩

HTTP рассматривает запросы отдельно; приложение связывает их через cookie, session ID или token.

Модуль 23: СостояниеSlide #70

HTTP stateless

🖥️Browserrequest A
→
⚙️Backendresponse A
🖥️Browserrequest B
→
⚙️Backendresponse B

Сам по себе второй запрос не обязан содержать связь с первым. Идентичность и контекст добавляются поверх HTTP.

Модуль 23: СостояниеSlide #71

Access tokenЧасть утверждений в подписанном токенеСам token в header/cookie
Cookie с даннымиНа клиенте, ограниченный объёмЗначение cookie по правилам домена

Cookie в HTTP

Сервер устанавливает cookie в ответе, а браузер возвращает её в последующих подходящих запросах.
